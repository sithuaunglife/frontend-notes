# PostgreSQL

## Facts
- SQL databases are generally relational databases that use SQL (Structured Query Language).
- `INTEGER` is represent whole numbers like `1` `25` `1000` `5000000`.
- `BIGINT` is bigger whole numbers like `3000000000`, `900000000000`.
- `DECIMAL` is like `0.5`, `1.5` represents the `.`.
- `TEXT` is just text.
- `VARCHAR` is text capped at n characters like at `VARCHAR(20)` it is capped at 20.
- `CHAR(2)` it is fixed and in this case the value is 2 characters long.
- `TIMESTAMP` is date plus time.
- `INTERVAL` is a period/duration of time.
- `UUID` is globally unique ID and it is already created and randomly created string. It is great for storing unique IDs.
- `ENUM` is like radio button.
- You can give permission to other users from the PostgreSQL `root` user.
- `ILIKE` is used for pattern matching/searching. Unlike `LIKE`, which is case-sensitive in PostgreSQL, `ILIKE` is case-insensitive.
- `SERIAL` is auto increasing one by one like 1,2,3.
- `TIMESTAMPTZ` is date plus time with timezone handling.
- `TRUNCATE TABLE products RESTART IDENTITY;` it delete all products and also restart the ID from the beginning.
- `DELETE FROM products WHERE` deletes rows/data from the `products` table.
- `UPDATE products SET ... WHERE` updates existing rows/data in the `products` table.
- Schema is the structure/blueprint of the data, telling what rows and columns the data will have and what rules they follow.
- `id` `created_at` `updated_at` can be automatically generated by the system if you define them/configure them that way, so you don't always need to manually give their values.
- `SELECT * FROM products` it gets all data from the `products` table.
- `SELECT name, price FROM products;` it gets only `name` and `price`.
- `SELECT * FROM products WHERE category = 'laptop';` `WHERE` filter things.
- `DELETE FROM products WHERE product_id = 6;` this delete the product.
- The deleted id are not used again when you create a new product it become a new id. For example if id 12 product row got deleted the new id row become 13 not 12.
- `UPDATE products SET price = 1300, updated_at = current_timestamp WHERE product_id = 1` it updates the `price` and updated time.
- You can write SQL statements in capital or small letters, but capital letters are the standard for SQL keywords/statements.
- `DELETE FROM products;` this delete all products from the `products` table.
- `WHERE` is same as `if`. It filters data based on a condition.
- There are operators in database.
- `AND` means both conditions must be true.
- `IN` lets you choose/filter multiple possible values at once.
- `WHERE name LIKE '%min%'`. `LIKE` is like searching for that thing. `%min%` is like a search feature.
- `ASC` is ascending. Example A to Z.
- `DESC` is descending. Example Z to A.
- `ORDER BY category ASC` it is ascending.
- `SET price = 1300, category = 'phone'`. `SET` can update multiple columns at the same time.
- `LIMIT 5 OFFSET 10 LIMIT`. `LIMIT 5` only show 5 things and `OFFSET 10` skip 10 things. `OFFSET` is how many things you want to skip. Example - If I use OFFSET 10 I skip 1 to 10 products and it start from 11th product and if I use LIMIT 5 it limit to 11th to 15th products.
- `COUNT(*)` counts how many rows are in the result.
- `SUM(stocks)` it sum up all the values in the `stocks` column.
- `AS` means giving a temporary name (alias) to something. It is similar to a variable name.
- `AVG()` is average the values.
- `MAX()` is the maximum value. It doesn't have to be price or one product.
- `GROUP BY` is grouping those data by a column.
- `HAVING AVG` is filtering groups based on their average.
- `IF NOT EXISTS` means create something only if it does not already exist.
- `DROP TABLE IF EXISTS` delete the table if it exists.
- `JOIN` = combining related data from multiple tables.
- `LEFT JOIN` = keep all rows from the left table, even if there is no match.
- `RIGHT JOIN` = keep all rows from the right table, even if there is no match.
- `RESTRICT` = don't allow the parent action if related records would be affected.
- `CASCADE` = the related records follow the parent's action. Example: deleting a category can delete its related menu items.

## Terminal Commands
### Docker

**Running PostgreSQL in Docker**
```bash
docker run --name my-postgres `
  -e POSTGRES_USER=root `
  -e POSTGRES_PASSWORD=asdffdsa `
  -e POSTGRES_DB=my_store `
  -p 5432:5432 `
  -v "$(pwd)/data/postgres:/var/lib/postgresql/data" `
  -d postgres:16
```
- `--name my-postgres` gives the container a friendly name so it can be referred to later.
- `-e POSTGRES_PASSWORD=...` sets an environment variable inside the container for the postgres user's password.
- `-e POSTGRES_DB=my_store` automatically creates the my_store database when the container starts for the first time.
- `-p 5432:5432` maps port 5432 on the host machine to port 5432 inside the container.
- `-v "$(pwd)/data/postgres:/var/lib/postgresql/data"` says: "store this container's data directory at Desktop/learn-databases/data/postgres on my actual machine — not somewhere hidden inside Docker." You can now literally open that folder in Finder/Explorer and see PostgreSQL's raw data files.
- `-d` runs the container in detached mode, meaning it runs in the background.
- `postgres:16` specifies the PostgreSQL Docker image and version 16 to run.
- Without a volume, all your data vanishes the moment the container is removed. A volume stores data outside the container, on your actual machine, so it survives even if the container is deleted and recreated. Docker gives you two flavors: Named volume — Docker manages the storage location for you, somewhere inside Docker's own internal storage (e.g., `my_postgres_data:/var/lib/...`). Bind mount — you choose the exact folder on your machine, and Docker writes directly into it. This is what you want if you'd rather see and back up the data yourself.


**Connect to PostgreSQL inside Docker**
```bash
docker exec -it my-postgres psql -U root -d shop
```
- `docker exec` → execute a command inside a Docker container
- `-it` → interactive terminal
- `my-postgres` → container name
- `psql` → PostgreSQL command-line tool
- `-U root` → connect as user root
- `-d shop` → connect to the shop database


- `-\l` show a list of databases.
- `-\dt` show a list of tables.
- `-\c` connect to a database.
